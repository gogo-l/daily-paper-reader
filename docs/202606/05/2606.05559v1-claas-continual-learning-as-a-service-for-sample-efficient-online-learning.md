## 摘要
部署的大型语言模型智能体必须适应动态环境中的分布偏移。理想情况下，适应可以从积累的智能体经验中执行，并在迁移到未来任务时保留先前的能力。然而，智能体的动作和环境转换在每个场景中只能采样一次，因为现实世界环境无法简单地重置。为此，我们研究了一种经验式和在线持续学习设置，其中智能体从一系列场景中学习。我们提出了持续学习即服务（CLaaS），这是一个使智能体在部署期间能够改进的系统，其功能隐藏在聊天 API 之后。为了提高样本效率，CLaaS 将交互轨迹存储在经验回放缓冲区中，以便在异步训练过程中重用梯度。我们在对抗性任务上评估了 CLaaS，结果表明，参数化更新比上下文学习带来了更好的前向迁移和更少的遗忘，而回放是样本效率的关键选择。

## Abstract
Deployed large language model agents must adapt to distribution shift in dynamic environments. Ideally, adaptation can be performed from accumulated agent experiences and retain prior capabilities while transferring to future tasks. However, agent actions and environmental transitions can only be sampled once per scenario, as real-world environments cannot be trivially reset. To this end, we investigate an experiential and online continual learning setting in which agents learn from a stream of scenarios. We propose continual learning as-a-service (CLaaS), a system which enables agents to improve during deployment, abstracted behind a chat API. To increase sample efficiency, CLaaS stores rollouts in an experience replay buffer for gradient reuse during asynchronous training. We evaluate CLaaS on an adversarial task, demonstrating that parametric updates lead to superior forward transfer and less forgetting than in-context learning, with replay being a critical choice for sample efficiency.

### 2. 论文提出的方法论

*   **核心思想**
    *   CLaaS 的核心是让智能体在持续的、不可重置的场景流中进行 **参数化** 的在线持续学习，而非依赖临时的上下文。
    *   通过将智能体的交互轨迹存储在 **经验回放缓冲区 (Experience Replay Buffer)** 中，并在后台异步地对模型参数（LoRA 适配器）进行梯度更新，从而实现样本的高效重用，提升学习效率和泛化能力。

*   **关键技术细节与算法流程 (Algorithm 1)**
    1.  **系统架构 (Architecture)**
        *   CLaaS 作为一个后端服务，封装了与任何前端智能体程序 (Agent Harness) 交互的聊天 API。
        *   其内部包含一个 vLLM 推理服务器和一个 veRL 训练引擎，形成一个持续的改进闭环。
        *   推理服务器负责执行任务并收集轨迹 (Rollouts)，训练引擎则异步地从缓冲区采样数据进行学习，更新后的 LoRA 权重会被热重载回推理服务器。

    2.  **异步训练与经验回放 (Asynchronous Training and Experience Replay)**
        *   **轨迹收集**：智能体按照当前策略 \(\pi_{\theta_k}\) 与环境交互，完成一个场景，得到轨迹 \(\tau_i\) 及其奖励 \(r_i\)。
        *   **缓冲区管理**：轨迹被存入容量为 \(B_{max}\) 的缓冲区 \(B\)。当缓冲区满时，按先进先出策略移除最旧的样本。
        *   **训练触发与采样**：当缓冲区内的样本数达到阈值 \(B_{min}\) 时，异步训练进程启动，从缓冲区中 **均匀采样** 一个批次 (minibatch) 的轨迹进行梯度更新。这与传统 PPO 同步收集再重复遍历整个批次的训练方式不同。
        *   **样本效率机制**：为实现样本高效，每条轨迹在缓冲区中最多可被重用 \(A_{max}\) 次梯度更新后才会被淘汰。这允许数据跨场景复用，极大提升了梯度利用率。

    3.  **优化目标 (Objective Function)**
        *   CLaaS 评估了三种无关节统计量的策略梯度算法：REINFORCE++、PPO 和 SDPO。
        *   核心采用 **PPO 的裁剪替代目标函数**，但针对回放导致的策略陈旧性问题，引入了重要性采样比率 \(\rho_{i,t}(\theta)\) 对更新进行重加权，并通过裁剪参数 \(\epsilon\) 约束过度离线的策略更新。
        *   损失函数公式 (简化)：
            \[
            \ell(\tau_i, \theta, r_i) = \sum_{t=1}^{T} \min \left( \rho_{i,t}(\theta) \hat{A}_{i,t}, \text{clip}(\rho_{i,t}(\theta), 1-\epsilon, 1+\epsilon) \hat{A}_{i,t} \right)
            \]
            其中，\(\rho_{i,t}(\theta)\) 是当前策略与采样策略在时刻 \(t\) 的 token 级别概率比，\(\hat{A}_{i,t}\) 是优势估计。

### 3. 实验设计

*   **数据集与场景**
    *   **任务**：对抗性攻击防御任务，模拟持续变化的非稳态分布。
    *   **数据集**：使用了 **IH-Challenge** 基准中的复合类别 (composite category)，包含 100 个随机场景。
    *   **场景设计**：一个带有多条复杂规则的系统提示 (防御者) 对抗一个不断学习的攻击者。攻击者通过 ICL 和验证器反馈在3轮对话中动态调整攻击策略，创建了一个非平稳、不断升级的挑战。未适应的基线模型防御成功率从单轮攻击的 54.3% 急剧下降到 3 轮攻击的 27.2%。

*   **评测基准与指标**
    *   将 100 个场景划分为 \(K=5\) 个连续的分割 (split)，模仿在线学习的数据流。
    *   **前向迁移 (Forward Transfer)**：在训练到当前分割后，对未来未见分割的性能提升。指标越高越好。
    *   **遗忘 (Forgetting)**：继续训练后，对先前学习过的分割的性能退化。指标越低越好。
    *   **最终性能 (Final Rate)**：最后检查点在所有分割上的平均防御成功率。

*   **对比方法**
    *   **基线 (Baseline)**：不做任何适应的基础模型。
    *   **ICL 基线**：在防御者的系统提示中累积之前的验证器反馈信息，作为非参数化对比。
    *   **CLaaS 下的三种策略梯度方法**：PPO, REINFORCE++ 和 SDPO。超参数经过手动优化。

### 4. 资源与算力

*   **硬件配置**：实验使用了 **2 块 NVIDIA H100 GPU**，一块用于模型的异步训练，另一块用于推理服务。
*   **模型**：基础模型为 **Qwen3-8B**，参数更新采用 LoRA 适配器 (r=32, α=64)。
*   **额外说明**：论文在致谢部分提及得益于 Incept Labs 和 Ritankar Das 赞助的计算资源。

### 5. 实验数量与充分性

*   **主实验**：对 4 种主要方法（Baseline, ICL, REINFORCE++, PPO, SDPO）进行了对比，每种方法在 **3 种不同的数据随机打乱** 和 **3 轮训练运行** 的设定下执行，指标平均超过了 **9 次试验**，确保了统计稳定性。
*   **消融实验**：
    *   针对 REINFORCE++，详细消融了经验回放缓冲区中最大重用次数 \(A_{max}\) 的影响，设置了 \(A_{max} = \{1, 5, 25, 50\}\) 四组实验，以展示回放重用对样本效率的关键作用及其潜在风险。
    *   在附录中，比较了 SDPO 和 REINFORCE++ 在不同 \(A_{max}\) 下的最终性能，揭示了 SDPO 对更高回放年龄的鲁棒性。
*   **实验充分性评估**：实验设计是**充分且客观公平的**。它在严格控制的非稳态环境下比较了参数化与非参数化方法，通过多次试验和标准误差保证了结果的可靠性。消融研究清晰地验证了核心设计（经验回放）的有效性和其参数敏感性。

### 6. 论文的主要结论与发现

1.  **参数化更新的优势**：使用 CLaaS 进行参数化在线学习，在对抗性分布偏移下的 **前向迁移能力远超 ICL**，且 **遗忘现象显著减少**。
2.  **SDPO 表现最佳**：在对比算法中，**SDPO (Self-Distillation Policy Optimization)** 达到了最高的最终防御成功率（75.2%），**是 ICL (24.1%) 的 3 倍以上**，同时遗忘率仅为 ICL 的一半。
3.  **经验回放是核心**：经验回放缓冲区是提升样本效率的 **关键设计**。适度增加轨迹的重用次数（\(A_{max}\)）能显著提升泛化性能，但过高的 \(A_{max}\) 会因策略陈旧性导致训练崩溃。
4.  **SDPO 的鲁棒性**：得益于 EMA 教师模型提供的平滑信号，SDPO 能容忍更高的回放年龄（\(A_{max}=50\) 仍表现最佳），而 REINFORCE++ 在 \(A_{max}=50\) 时崩溃，显示出其算法效率和对离线数据的鲁棒性更高。

### 7. 优点

*   **创新的系统架构**：首次将持续学习抽象为“即服务”模型，通过一行代码即可集成，极大地降低了实际应用门槛，实现了部署期间的实时改进闭环。
*   **解决核心挑战**：直接解决了真实环境不可重置和在线学习样本效率低两大难题，提出了切实可行的异步训练和经验回放方案。
*   **扎实的实验验证**：在动态对抗的非稳态环境中证明了方法的有效性，实验指标（前向迁移、遗忘）设计贴合持续学习的本质，消融实验清晰地揭示了关键机制。
*   **方法对比全面**：不仅对比了参数化与非参数化方法，还对比了多种策略梯度算法，并深入分析了它们在不同回放设置下的特性，尤其是 SDPO 展现出的显著优势。

### 8. 不足与局限

*   **任务与模型的局限性**：实验主要基于文本对抗攻击这一特定任务，且仅在 Qwen3-8B 单一模型上验证。其在更广泛的智能体任务（如工具调用、具身智能）和更多样化的模型家族上的泛化性有待考证。
*   **安全性风险**：论文可能未充分考虑持续学习机制本身被恶意攻击者操纵的风险，例如通过构造特定模式的交互来污染回放缓冲区，从而诱导智能体学习到有害或错误的行为。
*   **超参数敏感性**：系统性能高度依赖 \(A_{max}\) 等关键超参数的设定，不恰当的选择可能导致性能崩溃，这增加了实际部署中调参的难度和成本。
*   **依赖验证器**：系统的学习信号完全依赖于一个准确的环境验证器。在奖励信号稀疏或定义模糊的真实场景中，方法的有效性可能受限。尽管 SDPO 尝试利用文本反馈，但其根基仍是验证器的二值或文本输出。
