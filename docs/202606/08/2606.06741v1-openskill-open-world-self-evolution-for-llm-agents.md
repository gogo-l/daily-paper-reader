## 摘要
自演进智能体需要在部署后适应，但现有方法假设存在可用的学习循环，例如精心策划的技能、成功的轨迹或验证信号。真实的开放世界部署可能不提供这些，只提供一个任务提示。在这项工作中，我们研究开放世界自演进，其中智能体必须从头开始构建其技能和验证信号，使用开放世界资源但没有任何目标任务监督。我们提出OpenSkill，一个引导这一循环的框架：它从文档、代码仓库和网络中获取扎根知识和验证锚点，将它们合成为可迁移技能，并在基于锚点而非目标答案的自建虚拟任务上优化这些技能。因此，开放世界既提供了要学习的知识，也提供了一个独立于监督的实践环境，目标任务的监督仅保留用于最终评估。在三个基准和两个目标智能体上，OpenSkill在满足无监督约束的同时达到了最佳的自动通过率。分析表明，其技能可以在不同模型间迁移而无需针对模型的适配，并且其自建的验证器尽管从未接触过真实结果，却与之保持一致。

## Abstract
Self-evolving agents requires adaptation after deployment, but existing approaches assume a usable learning loop, such as curated skills, successful trajectories, or verifier signals. Real open-world deployments may provide none of these, offering only a task prompt. In this work, we study open-world self-evolution, where an agent must build both its skills and its own verification signals from scratch, using open-world resources but no target-task supervision. We propose OpenSkill, a framework that bootstraps this loop: it acquires grounded knowledge and verification anchors from documentation, repositories, and the web, synthesizes them into transferable skills, and refines those skills against self-built virtual tasks grounded in the anchors rather than in target answers. The open world thus supplies both the knowledge to be learned and a supervision-independent practice environment, with target-task supervision reserved for final evaluation. Across three benchmarks and two target agents, OpenSkill attains the best automated pass rate while satisfying the no-supervision constraint. Analysis shows its skills transfer across models without model-specific adaptation, and its self-built verifier aligns with ground-truth outcomes despite never accessing them.

### 2. 论文提出的方法论

OpenSkill是一个三阶段的引导性学习框架，其核心思想是**将开放世界同时作为学习材料和独立于监督的实践场所**。

- **核心思想**
  - 将技能习得从依赖模型内部知识（参数化知识）或目标任务反馈，转变为从公开的外部资源中提取和提炼。
  - 构建一套自建的虚拟测试环境，其验证信号扎根于开放世界的可验证事实，以此取代目标任务的真实测试，实现无监督的自我完善。

- **关键技术细节与流程**
  整个流程严格遵循**信息隔离（Leakage Barrier）**原则，确保目标任务的监督信号仅在最终评估阶段才被引入。

  - **阶段一：开放世界知识获取 (Open-World Knowledge Acquisition)**
    - **技能知识获取 (D)**：基于任务指令 \(I_i\) 和环境 \(E_i\)，通过一个深度研究型LLM智能体检索公开的文档、API、论文、教程等，生成背景知识文档 \(k_i\)。然后，一个技能规划器（Skill Planner）将 \(k_i\) 合成为一份结构化的技能计划 \(p_i\)，明确技能架构、关键过程和领域规则。
    - **验证知识获取 (Dv)**：单独启动一个检索流程，专门提取可作为验证锚点的独立、可查证信息 \(k_{vi}\)。例如，知名数据集的统计不变量（如行数）、标准函数库的输出范围、官方文档中的参考值等。

  - **阶段二：无泄露技能演进 (Leakage-Free Skill Evolution)**
    - **生成初始技能**：基础智能体 \(\pi_\theta\) 根据技能计划 \(p_i\) 和知识 \(k_i\) 生成初始技能集 \(\hat{S}^{(0)}_i\)。
    - **构建虚拟验证器 (Virtual Verifier)**：一个独立的验证智能体 \(g\) 依据从阶段一获取的验证知识 \(k_{vi}\)，生成一个基于确定性断言（如Pytest测试）的虚拟测试集 \(\tilde{T}_i\)。此测试集不接触真实测试，而是检查输出是否满足从开放世界获取的已知事实。公式如下：
      \[\tilde{T}_i = g(I_i, E_i, k_{vi})\]
    - **迭代优化**：在当前技能集 \(\hat{S}^{(j)}_i\) 执行后，用虚拟测试集评估其得分 \(\tilde{r}^{(j)}\)。
      \[\tilde{r}^{(j)} = \frac{1}{|\tilde{T}_i|} \sum_{k=1}^{K} \tilde{t}_{i,k} \left(\pi_\theta(I_i, \hat{S}^{(j)}_i, E_i)\right)\]
      若得分低于满分，系统会生成结构化失败诊断 \(F^{(j)}\)，判断失败原因为**实现错误(Bug)** 还是**知识缺口 (Knowledge Gap)**。若是知识缺口，立即触发一次针对性的开放世界检索 \(k^{(\text{gap})}_i\)。智能体依据反馈和可能的额外知识来修正技能，进入下一轮迭代 \(\hat{S}^{(j+1)}_i\)，直至虚拟测试满分或达到最大迭代轮次 \(J\)（设为3）。

  - **阶段三：零样本目标评估 (Zero-Shot Target Evaluation)**
    - 将优化完成后的最终技能集 \(\hat{S}^*_i\) 冻结，部署到目标智能体 \(\pi_{\theta'}\) 上。
    - **此时才解锁目标任务的真实验证**，执行并计算最终通过率，以此评估整个框架的真实效果。

### 8. 不足与局限

- **成本与延迟**：开放世界检索和虚拟验证造成显著的API调用成本和时间延迟，相较于封闭世界方法更为昂贵。
- **虚拟测试局限性**：
  - **可能过于简单**：虚拟测试可能无法完全模拟真实任务的复杂度和边界情况，导致对技能质量的评估过于乐观。
  - **源污染风险**：从开放世界获取的验证锚点如果本身就包含了目标任务的答案或变体信息，则可能造成监督泄漏。
- **外部知识依赖性**：框架性能极度依赖从开放世界检索到的信息的质量和准确性，公开资源可能存在噪音、过时或矛盾，框架本身需要人工介入来追踪和验证来源。
- **特定领域失效**：在“制造业”任务上，所有自动化方法（包括OpenSkill）的通过率都为0%，表明其在某些极端知识密集型或技能要求特殊的领域仍存在瓶颈。虚拟验证器在需要深度领域专业知识（如化学相似性搜索）时，也可能生成有意义的测试。
- **网络安全等风险**：
  - 自主从开放世界抓取并执行代码可能会引入安全风险，例如执行了来自不可信源的恶意代码。
  - 生成并执行大量的自动化虚拟测试，若不加以限制，可能会对目标系统或网络服务造成意外的负载或破坏。
