## 摘要
自主代理系统在部署后很大程度上是静态的：它们不从用户交互中学习，并且反复出现的故障会持续存在，直到下一次人类驱动的更新发布修复程序。自我进化代理应运而生，但所有进化都局限于文本可变的构件——技能文件、提示配置、记忆模式、工作流图——而未触及代理的框架本身。由于路由、钩子排序、状态不变式以及分发调度都存在于代码中，而非任何文本构件中，因此一整类结构性故障从文本层物理上是不可达的。我们认为，源代码级的调整是一种根本上更通用的媒介：它是图灵完备的，是所有文本可变范围的严格超集，以确定性的方式生效，而非通过基础模型的遵从性，并且不会在长上下文的漂移下退化。我们提出了MOSS，一个在生产级代理基座上执行源代码级自我重写的系统。每次进化都锚定于一批自动收集的生产故障证据，并通过确定性的多阶段流水线进行；代码修改委托给一个可插拔的外部编码代理命令行工具，而MOSS保留阶段排序和裁决。候选方案通过将证据批次在临时试验工作器上对候选镜像重放来验证，然后通过用户同意门控的就地容器替换进行提升，并带有健康探测门控的回滚。在OpenClaw上，MOSS在无人干预的情况下，单次循环中将四项任务的平均评分从0.25提升到0.61。

## Abstract
Autonomous agentic systems are largely static after deployment: they do not learn from user interactions, and recurring failures persist until the next human-driven update ships a fix. Self-evolving agents have emerged in response, but all confine evolution to text-mutable artifacts -- skill files, prompt configurations, memory schemas, workflow graphs -- and leave the agent harness untouched. Since routing, hook ordering, state invariants, and dispatch live in code rather than in any text artifact, an entire class of structural failure is physically unreachable from the text layer. We argue that source-level adaptation is a fundamentally more general medium: it is Turing-complete, a strict superset of every text-mutable scope, takes effect deterministically rather than through base-model compliance, and does not erode under long-context drift. We present MOSS, a system that performs self-rewriting at the source level on production agentic substrates. Each evolution is anchored to an automatically curated batch of production-failure evidence and proceeds through a deterministic multi-stage pipeline; code modification is delegated to a pluggable external coding-agent CLI while MOSS retains stage ordering and verdicts. Candidates are verified by replaying the batch against the candidate image in ephemeral trial workers, then promoted via user-consent-gated, in-place container swap with health-probe-gated rollback. On OpenClaw, MOSS lifts a four-task mean grader score from 0.25 to 0.61 in a single cycle without human intervention.

### 1. 论文的核心问题与研究背景
- **问题定义**：现有的自主代理系统（如OpenClaw）在部署后几乎保持静态，无法从用户交互中学习，反复出现的故障只能等待人工更新修复。

- **整体含义**：源代码级重写是一种图灵完备、确定性生效且不会因长上下文而退化的自适应介质，是文本可变范围的严格超集，从根本上解决了文本层不可达的故障修复问题。MOSS 正是在此思想上构建的、能够在生产级基座上完成自我源代码重写的系统。

### 2. 方法论：核心思想与关键技术细节
- **系统架构**：
  - **主容器**：运行面向用户的代理和进化服务，挂载 moss evo CLI。
  - **控制面 CLI**：9个子命令（status、batches、batch、start 等），通过 HTTP 与进化服务通信，利用 Unix Socket 与主机守护进程交互。
  - **外部编码代理 CLI**：可插拔，负责具体的代码改写，当前已集成 Claude Code、OpenAI Codex、DeepSeek-TUI 和 OpenCode，通过四方法接口与系统解耦。

  - **临时试验工人**：在候选镜像上重放故障批次，以生产等效环境和相同提示验证修改效果。
- **进化流程**（确定性的多阶段迭代）：
  1. **证据积累与定向进化**：通过定时任务（catch-up）或用户在对话中标记（flag）自动收集会话中表现不佳的片段，形成“批次”（batch）；进化由 start 命令触发，锚定具体批次而非探索性随机突变。
  2. **迭代循环**：实行预循环基线评估（对原始会话记录用任务评估阶段打分），随后进入七阶段流水线，每轮迭代生成四种裁决之一（CONVERGED / NEED_MORE_WORK / FUNDAMENTAL_LIMIT_MODEL / FUNDAMENTAL_LIMIT_ARCHITECTURE）。循环有深度可调（轻/标准/深），并设有无改进阈值的“高原护卫”强制收敛。
  3. **七阶段阶段流水线**：
     - Locate：读取基线会话和批次故障，输出诊断。
     - Plan：确定根因，指定修改文件与逻辑设计方案。
     - Plan-Review：质量把关，批准或拒绝计划（拒绝后循环修订）。
     - Implement：在内部代码库提交一个 commit。
     - Code-Review：对比计划审查代码差异，批准或拒绝（拒绝后重置到循环起点修订）。
     - Task-Evaluate：在临时试验工人中构建镜像并重放批次任务，用4级定性量表（强/足够/弱/缺失）对每个关键点打分。
     - Verdict：综合各任务评估和跨迭代关键点矩阵，输出裁决。
  4. **运行时验证**：临时试验工人（不与用户状态卷挂载、网络隔离）自主执行批次任务，检测仅在运行时才暴露的问题（如竞态条件、跨模块状态传播），而非依赖单元测试。
  5. **容器原位替换与安全机制**：
     - 用户需通过对话显式同意（moss evo apply），系统写入 swap-request 文件。
     - 主机守护进程监听到请求后停止旧容器，用候选镜像启动新容器；用户状态卷保留，保证状态不丢失。
