## 摘要
基于大语言模型的智能体日益部署来处理流式任务，但它们往往是一次性问题解决者，无法从过去的交互中学习。从经验中提炼的可复用技能为自我进化提供了自然基础，而高质量的技能策展是其中的关键瓶颈。现有方法要么依赖人工策展技能，要么规定启发式技能操作，或针对短视操作进行训练。然而，它们仍然难以从间接和延迟的反馈中学习复杂的长期策展策略。为应对这一挑战，我们提出SkillOS，一种经验驱动的强化学习训练方案，用于学习自我进化智能体中的技能策展。SkillOS将冻结的智能体执行器（用于检索和应用技能）与可训练的技能策展器配对，策展器根据累积经验更新外部SkillRepo。为了给策展提供学习信号，我们设计了复合奖励，并基于技能相关的任务依赖关系在分组任务流上进行训练，其中早前的轨迹更新SkillRepo，后续相关任务评估这些更新。在多轮智能体任务和单轮推理任务中，SkillOS在有效性和效率上始终优于无记忆和强记忆基线，且学习到的技能策展器能够泛化到不同的执行器骨干和任务域。进一步分析表明，学习到的策展器产生了更有针对性的技能使用，而SkillRepo中的技能逐渐演化为结构更丰富的Markdown文件，随时间编码出更高级的元技能。

## Abstract
LLM-based agents are increasingly deployed to handle streaming tasks, yet they often remain one-off problem solvers that fail to learn from past interactions. Reusable skills distilled from experience provide a natural substrate for self-evolution, where high-quality skill curation serves as the key bottleneck. Existing approaches either rely on manual skill curation, prescribe heuristic skill operations, or train for short-horizon skill operations. However, they still struggle to learn complex long-term curation policies from indirect and delayed feedback. To tackle this challenge, we propose SkillOS, an experience-driven RL training recipe for learning skill curation in self-evolving agents. SkillOS pairs a frozen agent executor that retrieves and applies skills with a trainable skill curator that updates an external SkillRepo from accumulated experience. To provide learning signals for curation, we design composite rewards and train on grouped task streams based on skill-relevant task dependencies, where earlier trajectories update the SkillRepo, and later related tasks evaluate these updates. Across multi-turn agentic tasks and single-turn reasoning tasks, SkillOS consistently outperforms memory-free and strong memory-based baselines in both effectiveness and efficiency, with the learned skill curator generalizing across different executor backbones and task domains. Further analyses show that the learned curator produces more targeted skill use, while the skills in SkillRepo evolve into more richly structured Markdown files that encode higher-level meta-skills over time.

- **整体含义**：论文提出 **SkillOS**，一种基于经验驱动的强化学习（RL）训练方案，使智能体能够自动学习如何在流式任务中持续策展技能库，从而实现更高效的自我进化，为构建长期可成长的智能体提供可行路径。

## 2. 方法论

- **核心思想**：将智能体系统解耦为**冻结的智能体执行器**（Agent Executor）和**可训练的技能策展器**（Skill Curator）。执行器使用外部技能库（SkillRepo）中的技能来完成任务；策展器则根据执行轨迹，通过 RL 学习如何插入（insert）、更新（update）、删除（delete）技能，以优化未来任务的性能。

- **关键技术细节**：
  - **技能表示**：每个技能存储为一个 Markdown 文件，包含 YAML 前置元数据（技能名称、描述）和 Markdown 正文（可执行知识、工作流、约束条件等）。
  - **执行流程**：对于每个新任务，从 SkillRepo 中用 BM25 检索相关技能子集，执行器据此与当前观测交互生成轨迹。策展器随后观察轨迹、自评正确性结果和已检索技能，通过函数调用执行一系列策展操作（插入/更新/删除），更新 SkillRepo。
  - **训练实例构建（分组任务流）**：通过为每个任务标注技能相关属性（topic、skill、concept 等），利用 Gemini-2.5-Pro 生成标签集，再基于属性相似度和依赖关系将任务分为相关组。训练时，对每一组任务顺序求解，早前的任务轨迹会通过策展器更新技能库，后续相关任务可立即评估这些更新对性能的影响，从而提供延迟但直接的下游学习信号。
  - **奖励设计**：使用复合奖励，结合四部分：
    - \(r_{\text{task}}\)：组内除第一个任务外其余任务的**平均成功率**（或正确答案率），反映策展对后续任务的增益；
    - \(r_{\text{fc}}\)：策展操作的有效函数调用比例；
    - \(r_{\text{cnt}}\)：由外部评判模型（Qwen3-32B）打分的**内容质量**奖励，评估技能是否抽象、可复用、可操作且忠实地轨迹；
    - \(r_{\text{comp}}\)：**压缩奖励**，鼓励技能库简洁，避免直接复制原始轨迹，计算方式为 \(1 - \frac{|S_i|}{|\chi_i|}\)，表示技能库大小相对于上下文长度的压缩程度。
  - **策略优化**：使用分组奖励策略优化（GRPO）。对每组任务采样 \(N\) 条独立 rollout，根据复合奖励计算优势值，采用裁剪替代目标函数更新策展器策略 \(\pi_S\)，且丢弃 KL 项以鼓励探索。

- **公式/算法流程（文字描述）**：
  1. 每个训练步采样一个任务组 \(G = (x_1, \dots, x_{|G|})\)，初始化空 SkillRepo。
  2. 对于组内每个任务 \(x_i\)：检索相关技能 \(\tilde{S}\)；执行器产生轨迹 \(\xi_i\)；策展器采样策展决策 \(c_i\)；应用操作更新 SkillRepo。
  3. 计算复合奖励 \(r = r_{\text{task}} + \lambda_f r_{\text{fc}} + \lambda_u r_{\text{cnt}} + \lambda_c r_{\text{comp}}\)。
  4. 利用 GRPO 优势计算和裁剪损失更新策展器参数。

## 3. 实验设计

- **数据集与场景**：
  - 多轮智能体任务：**ALFWorld**（具身家务任务，6 个子类，140 个测试任务）和 **WebShop**（模拟网购，500 个测试指令）。
  - 单轮推理任务：**AIME24、AIME25、GPQA-Diamond**（数学竞赛与研究生级问答）。
  - 训练数据：ALFWorld 和 WebShop 使用各自训练分割；推理任务从 DeepMath-103k 中采样 33,000 道题构建训练组。

- **对比方法**：
  - **无记忆（No Memory）**：每次任务独立求解，无外部记忆。
  - **ReasoningBank**：从轨迹提炼可复用洞察并存储为检索库。
  - **MemP**：从经验中提炼程序性记忆，并采用启发式记忆管理策略。
  - **SkillOS-base**：使用与 SkillOS 相同的策展器骨干（Qwen3-8B）但未经 RL 训练，仅依赖内在提示能力。
  - **SkillOS-gemini**：直接使用 Gemini-2.5-Pro 作为策展器（无 RL 训练），其余组件与 SkillOS 相同。

- **评估维度**：
  - 有效性：成功率和准确率。
  - 效率：交互步数（agentic）或消耗 token 数（reasoning，但实验中主要报告步数减少）。

## 4. 资源与算力

- **训练时长**：

- **实验数量**：论文在 **3 个领域**（ALFWorld, WebShop, 推理）上进行了主实验，并测试了 **4 种不同 executor 骨干**（Qwen3-8B / 32B / Gemini-2.5-Pro / Gemini-3.1-Flash-Lite），每组至少与 5 种基线对比（含无记忆和记忆基线）。此外还进行了：

## 6. 主要结论与发现

- **性能提升显著**：SkillOS 在所有基准上均**一致优于无记忆和强记忆基线**。例如，在 ALFWorld 上，面对 Qwen3-8B executor，SkillOS 将平均成功率从 ReasoningBank 的 55.7% 提升到 61.2%；同时交互步数从 21.1 降至 18.9。
- **效率优势**：SkillOS 实现更高成功率的同时，所需环境交互步数**更少**，表明其技能提供了更高效的决策指导，而非依赖更长试错。
- **策展能力泛化**：训练得到的 8B 策展器不仅能带来一致的性能增益，在**跨 executor 和跨任务域**时依然有效，甚至在某些情况下超越直接使用强大前沿模型（Gemini-2.5-Pro）作为策展器的效果，突显 RL 训练的专项能力。
- **技能演化现象**：训练过程中，策展器从最初以插入新技能为主，逐渐转向**更新和整合已有技能**；技能库从任务特异性技能向包含**元策略、故障恢复、系统化搜索**等更高阶技能的多样化结构演变。
- **技能使用更精准**：经 RL 训练的策展器给出的技能使用率更高，成功率更高，但平均每次任务调用的技能数量更少，表明技能选取更准确、更有针对性。

## 7. 优点

- **模块化解耦**：将执行器与策展器分离，便于独立优化策展能力，不修改执行器，易于与不同能力模型组合。
- **基于长期效用的 RL 训练**：通过分组任务流设计，将策展决策与下游任务性能关联，解决了延迟和间接反馈问题，使策展器能学习复杂的更新与删除操作。
- **复合奖励设计**：除任务结果外，引入函数调用有效性、内容质量、压缩度等中间奖励，为策展提供更密集、更直接的信号。
- **实证充分**：覆盖多类任务（具身交互和数学推理），多执行器泛化验证，以及丰富的定性与定量分析（技能操作分布演化、技能结构动态、利用归因），有力支撑了方法有效性。
- **技能表示通用且可解释**：采用 Markdown 技能格式，兼具结构化与可读性，便于审计和组合。

## 8. 不足与局限

- **检索机制简单**：目前使用 BM25 关键词检索，未利用密集向量或学习检索器，可能限制在大型技能库中的精准匹配。
- **技能表示扁平**：技能为单一 Markdown 文件，缺乏对可执行脚本的支持以及技能间的**层次化、组合关系**，导致某些需要程序性操作或层级调用的知识难以表达。
- **执行器冻结**：训练时仅优化策展器，未与执行器联合适应，可能限制了策展器与特定执行器特质的进一步对齐，且如果执行器本身策略与技能不兼容，策展器需独自承担适配压力。
- **实验局限**：尽管泛化至多种执行器，但仍均为相对大型的 LLM；在真实世界超长时、高度开放且存在干扰的任务流上尚未验证。
- **数据分组依赖外部标注**：任务分组需依赖外部 LLM（Gemini）生成属性，这个预处理步骤可能引入偏差或噪声，且会对极大规模数据带来额外成本。
- **奖励设计中的评判可靠性**：内容质量奖励依赖 Qwen3-32B 评判，其准确性可能影响技能质量信号的纯度。
