## 摘要
持续学习，即AI系统通过序列经验改进的能力，已引发广泛关注，但目前缺乏高质量的基准来评估它。我们推出了持续学习基准（CL-Bench），这是首个经过专家验证的困难基准，旨在衡量基于大语言模型的系统是否真正能从经验中改进。CL-Bench涵盖六个多样化的领域（软件工程、信号处理、疾病暴发预测、数据库查询、策略游戏和需求预测），每个领域都经领域专家验证，并设计为任务共享可学习的潜在结构（代码库布局、疾病暴发动态、对手策略），有状态系统可以在线发现这些结构，而无状态系统则不能。我们在多种智能体架构上评估了前沿模型，从朴素的上下文学习（ICL）到专用记忆系统，并引入增益指标以将学习与先验能力隔离开来。我们发现这些系统在持续学习方面仍有提升空间：智能体经常过拟合即时观测，或在实例间未能重用知识，而专用记忆系统也未能解决此问题——事实上，朴素ICL的表现优于专门用于记忆管理的系统。CL-Bench是首个跨多样化现实世界领域、使用专家验证任务评估持续学习，并将在线学习与底层模型能力隔离开的基准，表明了对更优持续学习系统的需求。

## Abstract
Continual learning, the ability of AI systems to improve through sequential experience, has attracted substantial interest, but no high-quality benchmark exists to evaluate it. We introduce Continual Learning Bench (CL-Bench), the first difficult, expert-validated benchmark designed to measure whether LLM-based systems genuinely improve with experience. CL-Bench spans six diverse domains (software engineering, signal processing, disease outbreak forecasting, database querying, strategic game-playing, and demand forecasting), each validated by domain experts and designed so that tasks share a learnable latent structure (codebase layout, disease outbreak dynamics, opponent strategies) that a stateful system can discover online but a stateless one cannot. We evaluate frontier models across several agent architectures, from naive in-context learning (ICL) to dedicated memory systems, introducing a gain metric to isolate learning from prior capabilities. We find that these systems leave headroom for improved continual learning: agents frequently overfit to immediate observations or fail to reuse knowledge across instances, and dedicated memory systems do not fix this -- in fact, naive ICL outperforms systems dedicated to memory management. CL-Bench is the first benchmark to evaluate continual learning across diverse real-world domains with expert-validated tasks and isolate online learning from underlying model capability, showing a need for better continual learning systems.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 基准任务设计原则
- **头部空间**（headroom）：初始表现远低于理论上限，且潜在结构不是通用离线知识，无法通过更强的基座模型替代学习。
- **共享潜在结构**：不同实例间存在可发现的规律（如数据库模式、频谱发射器集合、对手策略），能被有状态系统利用。
- **学习机制**：环境提供反馈（如测试失败、中间结果），使累积经验转化为有效知识。部分任务还引入**概念漂移**（如数据库迁移），要求系统适应而非盲从记忆。

### 2.2 任务简介
六个专家验证领域：
- **盲频谱监测**：从 90 次射频扫描中推断固定发射器集合，存在休眠信道。
- **代码库适应**：在 `jazzband/tablib` 和 `jd/tenacity` 仓库上解决 19 个真实 Issue，利用代码结构降低探索步数。
- **队列研究**：整合五个偏倚观察性研究，预测 36 个人口队列的生存率。
- **数据库探索**：在混淆模式的 SQLite 数据库上回答 40 个自然语言问题，中间经历数据库迁移。
- **可剥削扑克**：对抗三种固定策略的扑克对手（120 手），从下注模式推断对手模型。
- **销售预测**：基于轮换可见的单一店铺历史，预测 75 个产品-地点-年度组合的未来需求。

### 2.3 指标设计
- **奖励（reward）**：每实例定义的原始目标（如探索效率、预测误差）。
- **增益（gain）**：\( g_t = r^{sf}_t - r^{sl}_t \)，即同一系统在有状态与**无状态（重置）**下对同一实例的奖励差，纯化在线学习的贡献。
- **跨任务归一化**：用系统自己的无状态基线计算归一化增益 \(\tilde g = (\bar r^{sf} - \bar r^{sl})/(r_{\max} - \bar r^{sl})\)；归一化奖励则用固定外部基线（GPT‑5.4 ICL 的无状态表现）计算 \(\tilde r = (\bar r^{sf} - r_{\text{external}})/(r_{\max} - r_{\text{external}})\)。

### 2.4 稳定性-塑性分解
- 利用任务变体的边界将增益分解为：
  - **稳定性**：变体切换时（无变体内反馈）的增益，衡量跨变体知识保留。
  - **塑性**：变体内实例的增益，衡量在反馈下快速适应。

## 3. 实验设计：数据集/场景、基准和对比方法

- **任务场景**：上述六个现实领域，每个任务有明确的潜在结构和变体（如有概念漂移）。任务均经 2‑3 位领域专家在真实性、知识重用、学习改进三个维度上验证。
- **评估的模型**：Claude Opus 4.7、Claude Sonnet 4.6、Gemini 3.1 Pro、Gemini 3 Flash、GPT‑5.4。
- **持续学习系统（记忆范式）**：
  - **ICL**：完整对话历史（上下文允许范围内）。
  - **ICL Notepad**：模型自行维护结构化便签。
  - **Mem0**：自动语义提取记忆，并检索 top‑k。
  - **ACE**：每实例后更新剧本记忆。
  - **Claude Code** 与 **Codex**：头显模式智能体，自带上下文压缩。
- **对比方式**：在同一任务上比较 12 种系统-模型组合，并均报告有状态与无状态版本的指标。
- **统计处理**：每任务随机打乱实例顺序运行 5 次，报告均值和 95% 置信区间（Codex 因资源限制仅单次运行）。

## 6. 论文的主要结论与发现

1. **朴素 ICL 是最强基线**：全上下文 ICL（尤其是结合 Sonnet 4.6）在归一化增益（25.4%）和归一化奖励（22.3%）上均排名第一，远超出 Mem0、ACE 等专用记忆系统。
2. **专用记忆系统未解决学习问题**：ACE（增益 8.6%）成本最高但效果不佳；Mem0 和 ICL Notepad 未显示出对 ICL 的稳定提升，甚至有所退化。
3. **学习头部空间依然巨大**：最佳系统仅实现约 25% 的可用增益，多数任务上智能体表现出过拟合近期观察、未能跨实例重用知识或错误坚持早期信念。
4. **稳定性‑塑性差异显著**：不同系统呈现不同学习模式；ICL 和 Claude Code 更偏“塑性”（变体内快速适应），而 ICL Notepad 在某些模型上更偏“稳定性”（跨变体保留知识），但多数系统缺乏稳定的跨变体学习。
5. **成本效率上 ICL 亦有优势**：ICL 变体（如 Gemini Flash 仅 $7.6 即获 16.4% 增益）占据增益-成本 Pareto 前沿，高价计算未能成比例转化为学习增益。
