## 摘要
数据排练已成为缓解持续强化学习（CRL）中灾难性遗忘的主要方法。然而，现有工作仍局限于策略梯度框架，仅对行动者进行正则化，因为评论家正则化会导致性能下降。这种以行动者为中心的方法忽视了数据排练在价值函数近似中的潜力。此外，现有的CRL评估很少考虑任务序列重复的多循环环境，而这是现实世界中的一个关键场景，会加剧遗忘并影响可塑性。我们研究了在多循环环境中使用Q值正则化的深度Q网络的数据排练，并提出了Qreg+NWLU，它引入了两个简单的改进：（1）持续数据排练，在整个训练过程中动态收集和更新存储的Q值；（2）“无需等待”正则化，它立即应用，而不是在第一个任务之后。这些改进共同提高了学习效率、减轻了遗忘，并促进了知识迁移，在价值函数近似设置中优于Qreg和传统CRL方法。

## Abstract
Data rehearsal has emerged as a leading approach for mitigating catastrophic forgetting in Continual Reinforcement Learning (CRL). However, existing work remains confined to policy gradient frameworks, regularizing only actors due to the performance degradation incurred by critic regularization. This actor-centric approach overlooks the potential of data rehearsal for value function approximation. Moreover, existing evaluations in CRL rarely consider multi-cyclic environments where task sequences repeat, a critical real-world scenario that exacerbates forgetting and plasticity. We investigate data rehearsal for Deep Q-Networks using Q-value regularization in multi-cyclic settings and propose Qreg+NWLU which introduces two simple modifications: (1) continuous data rehearsal that dynamically collects and updates stored Q-values throughout training, and (2) "No-Wait" regularization that applies immediately rather than after the first task. Together, these modifications yield improvements in learning efficiency, forgetting mitigation, and knowledge transfer over Qreg and conventional CRL methods within value function approximation settings.

## 1. 论文的核心问题与整体含义

- **研究背景**：持续强化学习（CRL）旨在让智能体顺序学习多个任务，但面临灾难性遗忘和可塑性丧失。数据排练是缓解遗忘的主流方法，通过存储旧任务样本来对模型进行正则化。
- **现有缺陷**：
  - 当前数据排练方法几乎全部基于策略梯度框架（如Actor-Critic），仅对Actor（策略网络）做行为克隆正则化，而避免正则化Critic（价值网络），因为已有工作发现Critic正则化会导致性能退化。这导致基于值函数近似的方法（如DQN）在CRL中的潜力被忽视。
  - 现有CRL评估大多在单周期任务序列上进行，很少考虑多循环场景（任务序列重复多个周期），而真实场景中任务常会重复出现，多循环会放大遗忘和可塑性损失。
- **核心问题**：如何将数据排练与值函数正则化有效结合到DQN这类值-based方法中，并使其在多循环持续学习中表现稳定、高效。
- **整体含义**：弥补Critic正则化在CRL中的空白，提出简单改进，证明价值函数的数据排练在多循环环境中可以有效缓解遗忘、促进迁移，为价值-based CRL开辟新道路。

## 2. 方法论

- **基础方法 Qreg**：在标准DQN上增加一个排练重放缓冲区（RRB），存储旧任务的 `(s, a, Q_RRB)` 元组。训练当前任务时，额外添加 Q-值正则化损失：
  \[
  \mathcal{L}_{\text{Qreg}} = \lambda \frac{1}{N_{\text{RBS}}} \sum_{i=1}^{N_{\text{RBS}}} \left( Q_\theta(s^{(i)}, a^{(i)}) - Q_{\text{RRB}}^{(i)} \right)^2
  \]
  样本在任务结束后从当前回放缓冲区中随机选取，正则化仅从第二个任务开始应用。

- **Qreg 的问题**：
  - 仅从任务末期采样，样本多样性差，可能存储欠训练或不准确的 Q 值。
  - 存储的 Q 值永不更新，随训练推进变得陈旧。
  - 导致训练不稳定，尤其是任务间差异较大时（如首因偏差效应）。

- **改进方案 Qreg+NWLU（No-Wait Qreg with Live‑Updates）**：
  - **Live（连续采样）**：在整个训练过程中，以固定频率（如每2k步）从回放缓冲区最新的 `NRAH` 个样本中随机选取 `NRASS` 个加入 RRB，而非等待任务结束。增加样本多样性。
  - **Updates（动态更新）**：以相同频率更新 RRB 中属于当前任务的样本的 Q 值，避免Q值过时。需记录每个样本的任务ID。
  - **No-Wait（无需等待）**：得益于 Live，一旦 RRB 中有样本，立即开始 Qreg 正则化，无需等到首个任务结束，从而稳定早期学习。
  - 三者结合：在训练每一步时，按照上述频率执行 Live 添加、Updates 更新 Q 值；同时，如果 RRB 非空就计算 Qreg 损失并联合 DQN 损失更新网络。

- **算法流程**（详见论文 Algorithm 1）：初始化两个缓冲区，循环训练每个任务每个周期；每步与环境交互并存样本；按固定频率更新目标网络、更新 RRB 样本 Q 值、挑选新排练样本；训练时同时采样当前任务 batch 和 RRB batch，计算 DQN 损失与 Qreg 损失并更新参数。

## 3. 实验设计

- **环境与任务序列**：
  - **Minihack Room**：格子世界任务，5个子任务依次为 Room Random → Room Dark → Random Monsters → Random Trap → Room Ultimate，难度递增（视野受限、敌人、陷阱等），属于较硬的过渡。
  - **PLE Flappy Bird**：缩小管道间隙（100→80，每次减5），难度递增，属于较软的过渡。
  - **PLE Catcher**：增加水果下落速度（0.608→0.728，每次加0.03），难度递增，同样为软过渡。
  - 每个序列包含5个任务，固定顺序，重复训练4个循环，共600万步（每任务30万步）。

- **评价指标**：
  - **平均回报 G**：每个任务在评估时的平均得分。
  - **最终转移 F**：训练某任务结束后对另一任务性能的净变化，正值表示正迁移，负值表示遗忘。
  - **最差转移 W**：训练期间对另一任务的最低性能与开始时的差值，捕获训练过程中的遗忘。
  - 所有指标均以10为缩放因子便于显示。

- **对比方法**：
  - 常规基线：DQN、DDQN、Perfect Memory（回放缓冲区扩大至150万）、无CRL方法的DQN。
  - 主流CRL算法：PackNet、EWC、L2、MER。
  - 基础数据排练：Qreg（原版）。
  - 本文提出的 Qreg+NWLU。

- **实现细节**：所有方法统一使用 DQN 架构，回放缓冲区极小（5万），训练开始无预热，ε-贪婪固定5%，无任务间重置（PackNet除外）。评估每6万步进行，每次10个episodes，每个算法跑10个不同的随机种子。

## 4. 资源与算力

- 文中明确指出，实验在集群上运行，使用了多种 GPU 型号：NVIDIA A40、A100、L40s、H200，搭配 Intel Xeon Gold 6326、AMD EPYC 等CPU，所有节点内存 64 GB。
- 未给出具体的训练耗时、GPU 数量或总计算量，但环境（PLE、Minihack）计算效率较高，整体实验规模可控。

## 5. 实验数量与充分性

- **主实验**：在3个不同任务序列上，对比9种算法（DQN, DDQN, PM, PackNet, EWC, L2, MER, Qreg, Qreg+NWLU），每种算法10个随机种子。
- **消融实验**：对 Qreg+NWLU 的各个组件进行剥离，比较 Qreg+U、Qreg+L、Qreg+LU、Qreg+NWL，同样在三个环境中运行10个种子。
- **超参数敏感性**：针对 Qreg+NWLU 的关键超参数（λ、RRB大小、更新频率）提供了学习曲线，在三个环境中各用5个种子测试。
- **辅助分析**：展示了各方法在不同任务组合上的详细 F、W 指标矩阵，以及Q值范数变化曲线，用于分析稳定性。
- 评估较为全面：覆盖了软、硬任务过渡，度量了最终性能和遗忘动态，通过多种子汇报标准差，确保统计可靠性；对比方法囊括了多种CRL类别，且基线调参合理（对部分基线做了超参搜索）。总体而言，实验设计充分、客观、公平。

## 6. 主要结论与发现

- Qreg 在软过渡的 Flappy 和 Catcher 中表现尚可，但在较难的 Room 序列中出现严重不稳定，类似“首因偏差”，导致大量种子失败；而在成功案例中它能有效遏制训练过程中的遗忘（W值很低）。
- **Qreg+NWLU 在所有三个环境的所有任务上均显著优于所有基线**，达到最高的平均回报 G，同时保持最低的负迁移和最高的正迁移。
  - 在 Room 中，它克服了 Qreg 的不稳定性，4个周期后几乎达到最优性能。
  - 在 Flappy 和 Catcher 中，遗忘几乎消失，知识迁移更高效。
- 消融实验证明 “Live”、“Updates” 和 “No-Wait” 三者缺一不可：
  - 去除 No-Wait 会使 Room 中的稳定性回归到 Qreg 的水平。
  - 去除 Updates 则在 Flappy 和 Catcher 上会导致性能明显下降。
  - Live 对多样性贡献大，但单独使用效果不佳。
- Q 值范数分析表明，Qreg+NWLU 能使网络输出的 Q 值在任务切换时过渡更平滑、范围更窄，反映出更稳定的持续学习动态。
- 结论：基于价值函数的数据排练完全可以成功，但必须结合及时、动态的排练样本管理与立即正则化，才能达到稳健的性能。

## 7. 优点

- **填补研究空白**：首次深入研究 DQN（值-based）下的数据排练正则在多循环 CRL 中的表现，挑战了“Critic 正则化有害”的既有观念。
- **方法简洁高效**：仅通过连续采样、动态更新和立即正则化三个简单策略，几乎无额外复杂架构，便可大幅提升性能。
- **多循环评估范式**：引入任务重复的多周期评估，使遗忘分析更具现实意义，发现了单周期未能暴露的“首因偏差”等问题。
- **全面的实验验证**：涵盖多种环境类型、9种对比方法、细致的消融和超参数分析，并提供详细的转移矩阵和动态曲线，证据扎实。
- **分析深入**：利用 Q 值范数可视化解释了方法稳定性和遗忘缓解的内在原因。

## 8. 不足与局限

- **任务种类有限**：仅测试了 3 个游戏环境，且任务序列均为固定有序的软/中硬过渡，未包含随机任务顺序或完全无关的硬过渡（如不同游戏间的切换）。
- **依赖任务标签**：Updates 策略要求知道每个排练样本属于哪个任务，这在无明确任务边界的连续流式学习场景中可能难以实现。
- **仅适用于纯值函数方法**：本研究完全基于 DQN，未涉及 Actor-Critic 中 Critic 的正则化，而在那种架构下价值-策略的相互影响可能带来新的挑战。
- **排练方法单一**：仅考虑了简单的 L2 正则化形式的 Q 值匹配，未探索知识蒸馏、选择性采样等其他利用 RRB 的方法。
- **频率敏感**：Updates 和 Live 的采样频率需针对不同任务调整（论文附录提及了超参数搜索），可能增加调参负担。
- **现实扩展性未验证**：所有任务都是离散动作的游戏，缺少连续控制或真实机器人任务验证。
