## 摘要
我们提出了PEAM，一个在Minecraft中的参数化身代理记忆框架，它将代理记忆从推理时的检索转化为通过经验内化而驻留在参数中的技能。PEAM将一个用于开放式推理的慢速深思LLM与一个用于固化技能反射执行的快速参数模块配对。快速模块是一个多模态的专家混合LoRA架构，具有按类别物理隔离的适配器，能够在参数级别实现持续学习而不发生灾难性遗忘。我们将失败视为一级训练信号：通过联合行为克隆和对比目标，失败-纠正轨迹对被内化，因此代理不仅学习什么能够成功，还学习纠正后的动作与失败的动作有何不同。为了管理固化，PEAM引入了一个参数化价值分数来决定哪些经验应该被内化，以及一个无标度的自触发固化机制来决定何时内化，无需任务特定的手动调整阈值，使得代理能够自演化，因为触发器在不同任务分布间迁移时无需重新调整。在Minecraft中的实验表明，PEAM改进了长视界任务性能，减轻了对先前固化技能的遗忘，并相对于基于检索的化身代理和参数记忆变体，提高了参数与检索的效率。

## Abstract
We present PEAM, a Parametric Embodied Agent Memory framework in Minecraft that transforms agent memory from inference-time retrieval into parameter-resident skills internalized through experience. PEAM pairs a slow deliberative LLM for open-ended reasoning with a fast parametric module for reflexive execution of consolidated skills. The fast module is a multimodal Mixture-of-Experts LoRA architecture with per-category physically isolated adapters, enabling parameter-level continual learning without catastrophic forgetting. We treat failure as a first-class training signal: failure--correction trajectory pairs are internalized through a joint behavioral-cloning and contrastive objective, so the agent learns not only what succeeds but also how corrected actions differ from failed ones. To govern consolidation, PEAM introduces a parameterization-worthiness score for deciding which experience should be internalized, and a scale-free self-triggered consolidation mechanism for deciding when to internalize without task-specific hand-tuned thresholds, making the agent self-evolving as the trigger transfers across task distributions without re-tuning. Experiments in Minecraft show that PEAM improves long-horizon task performance, mitigates forgetting on previously consolidated skills, and improves parametric-versus-retrieval efficiency over retrieval-based embodied agents and parametric memory variants.

### 2. 论文提出的方法论
- **双层架构**
  - **慢速层（推理系统）**：基于 GPT-4o 的 LLM，负责开放式推理、代码合成、课程提议和结果验证，生成成功轨迹以及带纠正的失败-成功轨迹对。

  - **情景存储（Episodic Store）**：暂存成功轨迹 𝒟succ 和失败-纠正轨迹对 𝒟cpair。
- **固化管道三问：如何、哪些、何时**
  - **如何固化（How）**：使用联合损失更新对应类别适配器
    - 行为克隆（BC）损失：对成功轨迹做标准负对数似然。
    - PEAM-DPO 损失：对比失败轨迹（被拒绝）与纠正后轨迹（被选择），以轨迹级 DPO 优化，使适配器不仅学会成功行为，还能区分纠正与失败的动作模式。
    - 类别隔离：每个失败-纠正对只路由到其类别适配器，避免跨类别遗忘。
  - **哪些值得固化（What）**：参数化价值分数（PV）
    - 综合四方面：成本节省（未来调用频率×代码长度）、稳定性（成功率方差）、冗余（与已固化技能的语义重叠）、干扰风险（类别级别的结构性遗忘风险）。
    - 候选技能按 PV 排序，仅前 q 分位并满足得分阈值者进入固化。
  - **何时固化（When）**：自触发固化（STC）
    - 基于每个候选技能的近期失败率与历史基线的统计检验（Z 检验），无需人工设置绝对失败阈值，实现跨任务分布的无标度触发。
- **推理流程**
  - 首先尝试快速路径：任务路由到类别适配器，生成可执行代码并验证；若验证失败或无适配器，回退到慢速层。成功/纠正后的轨迹被写回情景存储，供后续固化使用。

### 7. 优点
- **认知启发的架构**：将互补学习系统理论落实到具身智能体中，实现从情景痕迹到参数技能的渐进转化。
- **物理隔离的防遗忘设计**：类别适配器完全不共享参数，从结构上消除跨类别干扰，是一种简洁而有效的持续学习方案。
- **充分利用失败信息**：不仅存储成功经验，还通过对比学习直接让模型从失败-纠正对中学习，使得参数技能更具鲁棒性。
- **无标度自触发固化**：STC 通过统计检验取代手工阈值，使智能体能根据自身统计自我决定何时固化，具有跨任务分布的迁移能力。
- **成本效益显著**：参数化路径极大减少了推理时的上下文重注入开销，延迟和 Token 用量大幅下降。
- **实践性方法论洞察**：揭示了量化部署、DPO 可部署性等实际问题，为社区提供了有价值的工程经验。

### 8. 不足与局限
- **环境单一**：所有实验基于 Minecraft，结论能否迁移到机器人操作、网页智能体等具身领域尚未验证。
- **固化类别有限**：仅 craft、gather、combat 三类，且导航等因失败模式不易产生纠正对而无法利用，限制了该方法的适用范围（对动作空间可纠正失败更有效）。
- **动作语法依赖性**：BC 对产生特定 JavaScript wrapper 格式的必要性被证实，但对工具调用 API 等其他动作空间的作用未知。
- **固化策略固定**：PV 权重和 STC 超参数虽固定不变，但仍是通过网格搜索选定，并非完全“免调参”，未来的动态调整策略可提升自主性。
- **跨分布评估的局限性**：触发稳健性实验使用轨迹重切片合成分布，与真实采集的分布仍有差距，外部效度待加强。
